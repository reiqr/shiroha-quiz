# Shiroha Quiz WebDAV 同步实现方案

> 更新日期：2026-08-15  
> 适用范围：Shiroha Quiz Web 版、Android 原生 Compose 版  
> 当前定位：用户侧云备份 / 云恢复 / 双端迁移功能设计文档

## 一、功能定位

WebDAV 同步功能面向普通用户，不是开发者内部工具，也不是后台管理系统。

它的核心目标是：

```text
用户自己的 WebDAV 云盘
↓
Shiroha Quiz 上传备份包
↓
另一台设备或另一端下载备份包
↓
用户确认后恢复
```

第一版不做实时同步，不做静默覆盖，不做字段级自动合并。它应先作为安全、可理解、可撤销的“云备份与云恢复”功能落地。

## 二、为什么优先做备份包同步

当前项目已经具备双端备份互认基础：

- Web 端已有完整数据备份 JSON。
- Web 端已有 Android 原生兼容 ZIP。
- Android 原生端已有完整 ZIP / JSON 备份导入导出。
- Android 原生端已经能识别 Web 备份中的 `crossPlatform` 数据。

因此 WebDAV 不应该重新设计题库数据结构，也不应该绕过现有导入导出逻辑直接同步内部字段。

推荐原则：

```text
WebDAV 只负责文件传输
备份格式继续由 Shiroha Quiz 现有导入导出逻辑负责
恢复动作继续走现有导入校验和用户确认流程
```

这样可以最大限度复用现有能力，降低破坏题库、错题、收藏、学习记录的风险。

## 三、第一版功能范围

### 1. WebDAV 设置

用户可以在设置页填写：

```text
WebDAV 地址
用户名
密码 / 授权码
远端目录
是否记住密码
```

默认远端目录建议：

```text
/ShirohaQuiz/backups/
```

需要提供：

- 测试连接
- 保存配置
- 清除配置
- 不保存密码的临时使用模式

### 2. 上传云备份

用户点击“上传云备份”后：

1. 当前端生成完整备份 ZIP。
2. 生成唯一文件名。
3. 如果远端目录不存在，尝试创建目录。
4. 上传 ZIP 文件。
5. 更新远端 `manifest.json`。
6. 显示上传结果。

文件名建议：

```text
shiroha-quiz-backup-20260815-153000-android.zip
shiroha-quiz-backup-20260815-153000-web.zip
```

不建议第一版覆盖同名文件。即使同一秒发生冲突，也应自动追加序号。

### 3. 云端备份列表

备份列表应展示：

```text
备份时间
来源端：Web / Android
软件版本
文件大小
题库数量
题目数量
是否包含错题 / 收藏 / 学习记录
```

列表来源优先读取 `manifest.json`。如果 `manifest.json` 缺失或损坏，则回退扫描 `backups/` 目录中的 `.zip` 文件。

### 4. 从云端恢复

恢复流程必须保守：

1. 用户选择云端备份。
2. 下载到本地内存或临时缓存。
3. 读取 `backup.json` 摘要。
4. 展示恢复预览。
5. 用户选择“合并导入”或“覆盖恢复”。
6. 二次确认。
7. 调用现有导入逻辑恢复。

不允许下载后自动覆盖本地数据。

### 5. 删除云端备份

允许用户删除远端备份文件，但需要二次确认。

删除后应同步更新 `manifest.json`。如果更新失败，至少要提示用户“文件已删除，但索引可能需要刷新”。

## 四、云端目录结构

推荐目录：

```text
/ShirohaQuiz/
  manifest.json
  backups/
    shiroha-quiz-backup-20260815-153000-android.zip
    shiroha-quiz-backup-20260816-101500-web.zip
```

不建议把备份文件直接散放在 WebDAV 根目录。

## 五、manifest.json 设计

`manifest.json` 不是唯一真相，只是备份列表索引。

示例：

```json
{
  "app": "Shiroha Quiz",
  "schemaVersion": 1,
  "updatedAt": 1786794000000,
  "backups": [
    {
      "fileName": "shiroha-quiz-backup-20260815-153000-android.zip",
      "path": "backups/shiroha-quiz-backup-20260815-153000-android.zip",
      "source": "android",
      "appVersion": "v0.9.8-native",
      "createdAt": 1786794000000,
      "size": 1234567,
      "sha256": "hex-string",
      "bankCount": 3,
      "questionCount": 1200,
      "includesWrongBook": true,
      "includesFavorites": true,
      "includesStudyRecords": true
    }
  ]
}
```

字段说明：

| 字段                            | 说明                      |
| ----------------------------- | ----------------------- |
| `app`                         | 固定为 `Shiroha Quiz`      |
| `schemaVersion`               | WebDAV 索引格式版本，不等于题库格式版本 |
| `updatedAt`                   | 索引更新时间                  |
| `backups`                     | 云端备份条目                  |
| `source`                      | `web` 或 `android`       |
| `sha256`                      | 可选但推荐，用于校验文件完整性         |
| `bankCount` / `questionCount` | 用于列表快速展示                |

如果 `manifest.json` 与远端实际文件不一致，实际文件优先，索引可以重建。

## 六、WebDAV 协议能力

第一版只需要这些方法：

| 方法         | 用途               |
| ---------- | ---------------- |
| `PROPFIND` | 列出目录内容           |
| `MKCOL`    | 创建目录             |
| `PUT`      | 上传备份文件和 manifest |
| `GET`      | 下载备份文件和 manifest |
| `DELETE`   | 删除备份文件           |

暂不需要：

- `MOVE`
- `COPY`
- `LOCK`
- `UNLOCK`
- 复杂增量同步协议

## 七、Android 原生端实现方案

Android 端应优先落地，因为没有浏览器 CORS 限制，体验最稳定。

### 1. 建议模块

```text
apps/android/app/src/native/java/com/yiqiu/shirohaquiz/webdav/
  WebDavConfig.kt
  WebDavClient.kt
  WebDavRepository.kt
  WebDavModels.kt
```

### 2. 职责划分

| 文件                    | 职责                                                           |
| --------------------- | ------------------------------------------------------------ |
| `WebDavConfig.kt`     | WebDAV 地址、用户名、授权码、远端目录、是否记住密码                                |
| `WebDavClient.kt`     | 低层 HTTP/WebDAV 请求，封装 `PROPFIND / MKCOL / PUT / GET / DELETE` |
| `WebDavRepository.kt` | 对接 `QuizRepository` 的备份导出导入                                  |
| `WebDavModels.kt`     | 远端备份条目、连接结果、上传结果、恢复预览                                        |

### 3. Android 页面入口

建议放在“我的 / 数据管理”页：

```text
数据管理
  本地备份
    导入题库
    导出题库
    导出全部
  WebDAV 云备份
    测试连接
    上传当前备份
    查看云端备份
    下载并恢复
```

不要把 WebDAV 混进题库普通导入页，避免用户误以为它是题库解析入口。

### 4. Android 存储安全

配置建议：

- WebDAV 地址、用户名、目录可以普通保存。
- 密码 / 授权码后续应使用加密存储。
- 第一版如果暂不接加密存储，需要明确提示“凭据保存在本机”。
- 不得把 WebDAV 密码写入备份包。

## 八、Web 端实现方案

Web 端可以接入，但需要明确浏览器限制。

### 1. 主要问题：CORS

很多 WebDAV 服务不允许浏览器跨域请求。即使账号密码正确，Web 端也可能因为 CORS 被浏览器拦截。

因此 Web 端第一版应这样设计：

```text
支持能跨域访问的 WebDAV
不承诺所有 WebDAV 服务都可用
失败时提示可能是 CORS 限制
```

### 2. Web 页面入口

建议放在“设置/导出”页：

```text
WebDAV 云备份
  WebDAV 地址
  用户名
  密码 / 授权码
  远端目录
  测试连接
  上传云备份
  刷新云端列表
  下载恢复
```

### 3. Web 端备份选择

Web 上传时优先使用：

```text
Android 原生兼容 ZIP
```

原因：

- 图片外置到 ZIP 的 `assets/` 中，减少 JSON base64 膨胀。
- Android 原生端恢复更稳定。
- Web 端也已经支持 JSON/ZIP 备份导入恢复。

完整 Web JSON 仍可保留为 Web 自身恢复入口，但不建议作为跨端云同步首选格式。

## 九、同步策略

### 第一版：手动同步

只做：

```text
手动上传
手动刷新列表
手动下载
手动确认恢复
```

优点：

- 行为清楚。
- 不会误覆盖。
- 容易解释给普通用户。
- 不需要复杂冲突合并。

### 第二版：半自动提醒

可以增加：

```text
启动时检查云端是否有新备份
本地数据变化较大时提醒上传
恢复前提示本地也先备份
```

仍然不自动覆盖。

### 第三版：冲突合并

后续再考虑：

```text
题库级合并
错题本合并
收藏合并
学习记录合并
同题库同 ID 冲突提示
```

这部分复杂度高，不建议第一版实现。

## 十、恢复模式

恢复时提供两种模式：

### 1. 合并导入

适合：

- 换设备后补充题库
- 从 Web 端导入到 Android
- 不确定是否要覆盖本机数据

行为：

```text
保留本地数据
新增云端题库
同名题库自动追加“_导入”
可映射的错题 / 收藏 / 记录一并合并
```

### 2. 覆盖恢复

适合：

- 新设备恢复完整数据
- 用户明确要以云端备份为准

行为：

```text
用云端备份替换本地题库、错题、收藏、学习记录
恢复前必须二次确认
建议恢复前自动提示先导出本地备份
```

## 十一、错误提示设计

常见错误需要给普通用户能理解的提示。

| 场景            | 提示建议                                        |
| ------------- | ------------------------------------------- |
| 地址为空          | 请填写 WebDAV 地址。                              |
| 地址不是 HTTPS    | 建议使用 HTTPS WebDAV 地址，避免账号泄露。                |
| 账号密码错误        | 登录失败，请检查用户名和授权码。                            |
| 目录不存在         | 正在尝试创建远端目录。                                 |
| 无权限创建目录       | 当前账号没有创建目录权限，请手动创建 `/ShirohaQuiz/backups/`。 |
| 上传失败          | 上传失败，请检查网络、空间容量或 WebDAV 权限。                 |
| 下载失败          | 下载失败，请稍后重试或检查文件是否已被删除。                      |
| manifest 损坏   | 云端索引损坏，将尝试扫描备份目录。                           |
| Web 端 CORS 失败 | 浏览器阻止了跨域请求，此 WebDAV 服务可能不支持 Web 版直连。        |

## 十二、安全边界

必须遵守：

1. WebDAV 密码 / 授权码不进入备份包。
2. 恢复前必须展示摘要。
3. 覆盖恢复必须二次确认。
4. ZIP 导入继续保留路径安全检查。
5. ZIP 导入继续保留大小和数量限制。
6. Web 端不要默认长期保存密码。
7. Android 端后续应使用加密存储保存凭据。
8. 上传失败不能清除本地数据。
9. 下载失败不能改动本地数据。
10. manifest 损坏不能影响已有备份文件恢复。

## 十三、测试清单

### 1. Android 基础测试

- WebDAV 配置保存和清除。
- 测试连接成功。
- 测试连接账号错误。
- 远端目录不存在时自动创建。
- 上传完整 ZIP。
- 下载完整 ZIP。
- 合并导入恢复。
- 覆盖恢复二次确认。
- manifest 损坏后扫描目录兜底。

### 2. Web 基础测试

- 支持 CORS 的 WebDAV 上传成功。
- CORS 失败时提示准确。
- 上传 Android 原生兼容 ZIP。
- 下载 ZIP 后走现有恢复逻辑。
- 不保存密码时刷新页面后密码清空。

### 3. 双端互通测试

- Android 上传，Android 下载恢复。
- Android 上传，Web 下载恢复。
- Web 上传，Android 下载恢复。
- Web 上传，Web 下载恢复。
- 包含图片题的 ZIP 恢复。
- 包含错题、收藏、学习记录的完整恢复。

### 4. 破坏性边界测试

- 云端文件被删除。
- manifest 缺失。
- manifest 内容不是 JSON。
- ZIP 中没有 `backup.json`。
- ZIP 超过大小限制。
- 网络中断。
- 上传到一半失败。
- 下载到一半失败。

## 十四、推荐开发顺序

### 第一阶段：Android 手动云备份

目标：

```text
Android 用户可以配置 WebDAV，并手动上传完整 ZIP 备份。
```

任务：

1. 新建 WebDAV 模块。
2. 支持测试连接。
3. 支持创建远端目录。
4. 支持上传完整 ZIP。
5. 支持基础错误提示。

### 第二阶段：Android 云端恢复

目标：

```text
Android 用户可以查看云端备份列表，下载并恢复。
```

任务：

1. 读取 `manifest.json`。
2. 扫描 `backups/` 目录兜底。
3. 下载 ZIP。
4. 展示恢复摘要。
5. 调用现有导入逻辑恢复。

### 第三阶段：Web 端接入

目标：

```text
Web 用户在支持 CORS 的 WebDAV 服务上也能上传和下载备份。
```

任务：

1. 设置页增加 WebDAV 面板。
2. 支持测试连接。
3. 支持上传 Android 原生兼容 ZIP。
4. 支持下载恢复。
5. 提示 CORS 限制。

### 第四阶段：半自动提醒

目标：

```text
减少用户忘记备份或恢复旧备份的概率。
```

任务：

1. 启动时检查云端最新备份。
2. 本地数据变更后提醒上传。
3. 恢复前提醒先备份本地。

## 十五、不建议第一版实现的内容

第一版暂不做：

- 实时同步。
- 后台自动覆盖恢复。
- 多设备同时编辑后的自动冲突合并。
- 题目级差异对比。
- WebDAV 服务商自动适配列表。
- 自建中转服务器。
- 把 WebDAV 当成题库后台发布系统。

原因：

这些功能会显著增加误覆盖、冲突和用户理解成本，不适合作为第一版。

## 十六、最终推荐方案

最推荐的落地路径是：

```text
先 Android
再 Web
先手动备份恢复
再半自动提醒
先复用现有 ZIP/JSON
后续再考虑增量合并
```

第一版验收标准：

```text
用户可以在 Android 原生版配置自己的 WebDAV。
用户可以一键上传完整 ZIP 备份。
用户可以看到云端备份列表。
用户可以下载备份并选择合并导入或覆盖恢复。
Web 版后续在支持 CORS 的服务上提供同类能力。
双端都不静默覆盖用户本地数据。
```

这就是 Shiroha Quiz WebDAV 功能最稳妥的用户侧实现方案。
