# 测试体系整理说明

> 更新日期：2026-09-17
> 涉及提交：`c385eb0`（清理过时测试）、`a0cc37c`（补充 DOCX 用例与完成流程断言）
> 本文说明整理的原因、判断依据与验证方式，供评审与后续维护参考。

## 一、整理背景

`gradlew testNativeDebugUnitTest` 全量执行时报 **5 个失败**，且长期存在。后果不是"测试挂了"，而是**这条防线失效**：

- 每次跑都刷同样的失败，真出现回归时无法分辨
- 被迫改用 `--tests` 筛选执行，等于放弃全量覆盖

| | 测试数 | 失败 |
| --- | --- | --- |
| 整理前 | 63 | 5 |
| 整理后 | 54 | 0 |

## 二、诊断思路

对 5 个失败逐个定位，关键判据是**时间线**：

```text
测试文件最后修改：2026-05-10      项目早期
解析器最后修改：  2026-07-24      相差 2.5 个月
```

对每个失败，比对「测试断言的行为」与「当前设计意图」：

| 失败用例 | 旧断言 | 实际行为 | 判定依据 |
| --- | --- | --- | --- |
| `ParserRuleSmokeTest` 规则顺序 | 12 条规则列表 | 13 条（多 `compact_answer_line`） | 后新增了规则，测试未同步 |
| 标准单选解析 | `标准优先解析` | `标准优先解析（单题紧凑修复）` | 解析器增强后新增标记 |
| 末尾判断题 | 答案 `[A]` | 答案 `[正确]` | 判断题答案格式已统一 |
| 两选项单选 | 期望"两选项单选题"警告 | 无该警告 | 现已能正确处理，警告已移除 |
| 错题进记录 | 提交 1 题即有记录 | 见第三节 ②（诊断曾出错） | — |

**判断原则**：实际行为若符合后来的设计决策（可在 CHANGELOG / README 中查到），则判为测试过时；找不到依据时才怀疑代码。

## 三、改动清单

### ① 删除 `QuizImportParserTest.kt`（−195 行）

10 个用例中 9 个与外部回归 100% 重复：

| 旧用例 | 外部回归用例 |
| --- | --- |
| 标准单选解析 | `01_standard_single` |
| 两选项单选 | `02_two_option_single` |
| 末尾判断题 | `03_trailing_judge` |
| 答案区合并 | `04_answer_section` |
| 双文件按题号合并 | `05_dual_file` |
| 其余 4 条 | 同理一一对应 |

**保留外部回归的理由**：它由 `manifest.json` 管理、含 63 个样例、当前全绿，是权威版本；旧文件只是它的过时子集。

**唯一边界**：旧文件里混有 1 个**非文本**用例（DOCX 解码），外部回归不覆盖，已单独补回（见 ④）。

### ② 修正 `QuizRepositoryExamTest.kt`

**诊断曾出错，此处如实标注**：

- 初次判断："记录粒度从一题一条改为一轮一条"
- 实际原因：测试**没有启动练习**，`submitPracticeQuestion()` 因 `currentPracticeQuestion()` 为 null 而返回 null（失败发生在 `assertNotNull`，不是记录断言）

**修法**：补前置初始化

```kotlin
QuizRepository.startPracticeSession(
    questionCount = 2,
    allowedTypes = setOf(QuestionType.SINGLE, QuestionType.MULTIPLE),
    randomize = false      // 固定题序，保证第 1 题答 B 必错
)
```

### ③ `runAll()` 改为反射自动发现

原实现是硬编码 14 个方法引用，且 JVM 入口断言 `== 14`。新增用例若忘记登记会**静默不执行**。

```kotlin
// 改前：val cases = listOf(::testA, ::testB, ...)
// 改后：
javaClass.declaredMethods.filter {
    it.name.startsWith("test") && it.parameterCount == 0 &&
        java.lang.reflect.Modifier.isPublic(it.modifiers)
}.sortedBy { it.name }
```

**配套约定**：`test*` 前缀只用于测试用例，辅助方法禁止使用该前缀命名。

**已知风险**：理论上有误收集可能。评估为可接受——后果仅是"多执行一个方法"，不影响 App；收益是新增用例不会漏跑。

### ④ 新增 `TextImportDecoderTest.kt`

外部回归样例均为纯文本，不经过 `TextImportDecoder`；删除 ① 后 Word 解码将失去单元测试覆盖。从原文件仅迁移这一条用例，不恢复其余 195 行。

### ⑤ 补充练习完成流程断言

原测试命名为 `until finished`，但只验证了"未完成时不生成记录"——属于**单边断言**，无法证明"该生成时确实会生成"。

补断言时首次运行即失败（`expected:<1> but was:<0>`），据此查出真实触发点：

```kotlin
fun completePracticeSession() {
    finishPracticeSessionIfNeeded(...)   // 记录在此产生
    resetPracticeState()
}
```

**结论**：仅"答完最后一题"不产生记录，必须显式结束练习。若不补这条断言，该行为差异不会被发现。

## 四、验证方式

| 验证项 | 命令 | 结果 |
| --- | --- | --- |
| 全量 JVM 测试 | `gradlew :app:testNativeDebugUnitTest` | 54/54 通过 |
| 外部解析器回归 | `run-regression.ps1` | 63/63 通过 |
| 新建文件中文编码 | PowerShell `-Encoding UTF8` 校验 | 通过 |

每条改动均有对照实验佐证：③ 的反射前后方法数、⑤ 补断言时的首次失败。

## 五、风险评估与取舍

| 项 | 风险 | 取舍理由 |
| --- | --- | --- |
| 删除 195 行测试 | 覆盖丢失 | 9/10 与外部回归重复，剩余 1 条已补回 |
| 反射发现 | 误收集辅助方法 | 靠命名约定规避，后果轻微 |
| 修改旧测试断言 | 被视为"改测试迁就代码" | 每处均可追溯到 CHANGELOG 中的设计决策 |
| ② 的初始化方式 | 依赖 `randomize = false` 保证题序 | 显式指定，避免随机导致的偶发失败 |

## 六、遗留事项

1. `8bef5d8`（备份图片回归）位于 `androidTestNative/`，需真机运行；因其加在已有方法内，JVM 桥接会通过 `runAll()` 执行到它（已验证通过）。
2. 外部回归与 JVM 单元测试之间没有交叉校验机制，两套独立维护。
